### 2-3. 확인된 데이터 품질 이슈

1. **강릉과 대관령 값이 사실상 동일** — 2025년 12개월 평균가가 1,427/1,423, 1,466/1,468 … 로 오차 0.5% 이내. 두 지역이 독립 관측이 아닌 동일 원천에서 파생되었을 가능성이 있어 **지역 비교 근거로 쓰기 전 원천 확인 필요**.
2. **실제 추이 테이블에 미래 날짜 존재** — `daily_market_trends`에 2026-08-06 ~ 2027-04-06 행이 있고 created_at은 2026-06-06. '실제값' 테이블에 예측값이 섞여 있을 가능성. 검증 시 조회 상한을 조사일로 제한해야 함.

**공간적 적절성 판정**

- 22~23 남부(광주·전남)는 **영산강·섬진강 수계**이고, 25년 강릉은 **동해안 소하천 권역**이다. 위 4개 댐은 어느 쪽에도 해당하지 않는다 → **직접 검증지표로 부적합**.
- 사례 지역 발전소는 `WT_POWER`에 존재한다: **보성강(전남 보성)**, **칠보(섬진강, 전북 정읍)**, **도암(대관령 인근)**, **강릉(오봉, WT_POWER_INFO 기준)**. 그러나 데이터가 **2023-07-26 ~ 2023-12-26의 172행뿐**이라 남부 사례의 핵심 시기(2022 하반기~2023 상반기)와 강릉 사례(2025)를 모두 벗어난다.
- `WT_POWER`(도암·칠보·강림)와 `WT_POWER_INFO`(강릉·섬진강·안흥)의 발전소명이 서로 달라 매칭 규칙 확인이 필요하다.

→ **결론: 수력발전량은 "보조자료"로만 언급하고 검증 지표에서 제외할 것을 권고.**

## Step 5 — 뉴스 기반 비정형 데이터 — **가장 큰 공백**

### 5-1. 항목별 보유 여부

| 항목 | `DRGHT_MONITORING_DAMAGE`(구) | `drought_article`(신) |
|---|---|---|
| 기사 제목 | ○ NEWS_TIT | ○ title |
| 기사 날짜 | ○ YYMMDD | ○ published_at |
| 본문/요약 | △ NEWS_ART **varchar(500) 절단** | ○ body (longtext, NULL 2건) |
| 지역 | △ SIDO_NM/SGG_NM **JSON 문자열 배열** | △ sido/sigungu (**7,848건 시도 공란**) |
| 영향 분야 | ○ IPT_CLA 7종 | ○ impact_code A1~A8 + `impact_field` 매핑 |
| 가뭄 영향 내용 | △ DMG_DTL(키워드 배열) | △ damage_detail(json) |
| 영향 등급 | ✕ | ○ `agg_period_grade` (관심/주의/경고/위험) |
| 출처·주소 | ○ NEWS_URL | ○ link |
| 분석 결과 | ○ 제목/본문 명사 | ○ title_nouns/body_nouns(json) |

### 5-2. 기간 공백이 결정적

```
1990 ─────── DRGHT_MONITORING_DAMAGE ─────── 2023-07-03
                                              ↑ 남부 사례 후반부 절단
                          [ 2023-08 ~ 2025-12-17 : 뉴스 전무 ]
                                                        ↑ 강릉 사례 전 구간
                                    2025-12-18 ─── drought_article ─── 2026-08
```

- **남부 사례(2022-01~2023-12)**: 광주·전남 관련 기사 **76건 확보**. 월 분포 — 2022-03(7), 05(1), 06(1), 07(11), 08(3), 09(2), 10(2), 11(13), 12(3), 2023-01(1), 02(7), 03(24), 05(1). 내용도 검증에 쓸 수 있는 수준(동복호 저수율 32.3%, 주암댐·평림댐 심각단계, 완도 제한급수, 전남 밭작물·양파 피해 등). **단 2023-06~12는 없음.**
- **강릉 사례(2025-01~12)**: 가뭄 기사 **사실상 0건**(2025-12-18 이후만 존재). 산불 뉴스 60건(2025-09~12)이 있으나 가뭄 영향 분류가 아님. → **강릉 사례의 뉴스 축은 현재 검증 불가.**

### 5-3. "가뭄영향 등급 → 관련 기사 → 실제 가뭄 영향" 구조

- 구조 자체는 **이미 구현되어 있다**: `agg_period_grade`(granularity=MONTH, dim_type=SIDO, bucket='2025-12', dim_key='강원', impact_code='A2', grade='위험') + `agg_period_grade_break`(분야별 등급 경계 기사수, 예 A1 198/227/405/473, A2 34/121/195/263) + `drought_article`(기사 원문·damage_detail).
- 그러나 **적용 구간이 2025-12~2026-08뿐**이라 두 사례 기간에는 결과가 존재하지 않는다.
- 연도·월 + 지역 + 영향분야 기준 조회는 **신규 데이터에 대해서만** 가능하다. 남부 사례는 `DRGHT_MONITORING_DAMAGE`로 조회 가능하나 등급이 없고 지역 필드 정규화가 필요하다.

> **발견된 지역 매핑 오류:** 광주광역시 관련 기사 상당수가 `SIDO_NM=['경기도', '전라남도'], SGG_NM=['광주시', '화순군']` 형태로 저장되어 **경기도 광주시로 오분류**되어 있다(동복호 관련 기사군). 남부 사례 기사 선별 시 반드시 보정해야 한다.

## Step 6 — 데이터 연결 가능성

목표 행: `사례 | 연월 | 지역 | 가뭄등급 | 뉴스 영향 | 농산물 가격 | 생산량 | 물가지수 | 기타 영향`

### 6-1. 연결 가능 여부

| 목표 컬럼 | 연결 가능 | 사용 테이블·컬럼 |
|---|---|---|
| 사례 | 신규 생성 | 기준표에 case_id 부여 |
| 연월 | ○ | 모든 테이블에 일자/연월 컬럼 존재 |
| 지역 | △ | 표기 4종 혼재, 표준코드 없음 |
| 가뭄등급 | **✕(사례기간)** | `agg_period_grade` — 2025-12 이후만 |
| 뉴스 영향 | △ 남부만 | `DRGHT_MONITORING_DAMAGE.IPT_CLA/DMG_DTL` |
| 농산물 가격 | △ | 강릉 ○(`daily_market_trends`), 남부 ✕(양파 5개월) |
| 생산량 | **✕** | DB에 없음 |
| 물가지수 | ○ | `drought_impact_fresh_food_price_index` |
| 기타 영향 | △ | ASOS 강수(강릉만), SPI(2022까지) |

### 6-2. 조인 규칙(현 DB로 가능한 최선)

```sql
-- 기준: 사례 × 연월 × 시도
기준표(case_id, ym, sido_std)
  LEFT JOIN drought_impact_fresh_food_price_index f
         ON f.base_date = STR_TO_DATE(CONCAT(기준표.ym,'-01'), '%Y-%m-%d')
        AND 표준화(f.province) = 기준표.sido_std          -- '광주광역시','전라남도','강원특별자치도'
  LEFT JOIN (SELECT DATE_FORMAT(trend_date,'%Y-%m') ym, location,
                    AVG(avg_wholesale_price) p, SUM(market_volume) v
             FROM daily_market_trends GROUP BY 1,2) t
         ON t.ym = 기준표.ym AND 지역매핑(t.location) = 기준표.sido_std   -- 강릉/대관령 → 강원
  LEFT JOIN (SELECT LEFT(YYMMDD,7) ym, 시도추출(SIDO_NM) sido,
                    IPT_CLA, COUNT(*) n
             FROM DRGHT_MONITORING_DAMAGE GROUP BY 1,2,3) n
         ON n.ym = 기준표.ym AND n.sido = 기준표.sido_std
```

### 6-3. 부족한 연결정보

1. **표준 지역코드 부재** — 시도 코드 컬럼이 어느 테이블에도 없다. 한글 시도명 문자열 매칭에 의존해야 하며, `전라북도`/`전북특별자치도` 병존, `['전라남도']` JSON 문자열, `광주`(소비지 시장명) vs `광주광역시`(시도) 동음이의 문제가 있다.
2. **농산물의 지역 축이 시도가 아니다** — `AGRI_PRICES.REGION`은 소비지 도매시장 소재지, `daily_market_trends.location`은 산지/시장명. 시도 매핑 규칙을 별도로 정의해야 한다.
3. **사례 기간 가뭄등급 부재** — 통합표의 핵심 축인 '기술결과 등급'이 두 사례 기간에 존재하지 않는다.

## 작업 원칙 준수 사항

- DB는 읽기 전용 조회만 수행했고 원본 데이터·스키마를 변경하지 않았다.
- 테이블·컬럼명만으로 의미를 확정하지 않고 실제 값·범위·결측을 조회해 확인했다. 의미가 확인되지 않은 항목(`AGRI_INSURANCE.AMOUNT`, `WT_POWER` 발전소명 불일치, 강릉/대관령 동일값)은 **확인 필요**로 표기했다.
- 데이터 존재와 검증 사용 가능성을 구분했다(예: 댐 발전량은 존재하지만 공간적으로 부적합).
- 가뭄과 가격·물가 변동의 인과관계는 단정하지 않았다. 검증 단계에서는 동일 시기의 기술결과·뉴스 영향·정형 데이터 변화의 **일관성**만 확인한다.
